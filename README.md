# Yandex SmartCaptcha AntiSpam

**Простой антиспам-плагин для WordPress** с невидимой капчей Яндекса и автоматическим переходом к видимому виджету после повторных отправок.

## Как работает адаптивная капча

1. При обычной отправке формы запускается **невидимая SmartCaptcha** без кнопки «Я не робот». **Яндекс самостоятельно показывает всплывающее задание** только пользователям, которых распознаёт как подозрительных.
2. Плагин считает попытки по IP и типу формы в течение заданного окна (по умолчанию **3 попытки за 10 минут**). Ошибка проверки, не заполненный токен или подозрительное содержимое комментария повышают риск раньше.
3. При следующем отображении формы вместо невидимого режима показывается **видимый стандартный виджет SmartCaptcha («Я не робот»)**. Яндекс может назначить дополнительное задание по своей оценке риска. Плагин **не может принудительно показать головоломку**, поскольку это решает сервис.
4. Сервер WordPress передаёт одноразовый токен в официальный API Яндекса и проверяет ответ и домен. Простая имитация JavaScript или User-Agent не обеспечивает прохождение проверки.

## Защищаемые формы

Из коробки:
- Стандартные комментарии WordPress, отправляемые через `wp-comments-post.php`.
- Форма входа `wp-login.php`.
- Стандартная регистрация `wp-login.php?action=register`.
- Восстановление пароля `wp-login.php?action=lostpassword`.

В настройках каждую защиту можно отключить отдельно, а авторизованных комментаторов — исключить (по умолчанию исключены). **Проверка входа по умолчанию выключена** для предотвращения случайной блокировки администратора при неверных ключах: включите её после тестирования. Остальные три встроенные формы включены по умолчанию.

**Ограничения версии 1.0:** формы конструкторов (Contact Form 7, Elementor, WPForms), WooCommerce, Gutenberg REST-comments, headless, AJAX/REST и собственные формы авторизации не защищаются автоматически. Для них нужен отдельный серверный адаптер. Не считайте наличие виджета на форме защитой без серверной валидации.

## Установка

1. Установите ZIP через **Плагины → Добавить плагин → Загрузить плагин** и активируйте.
2. В Yandex Cloud откройте SmartCaptcha, создайте капчу и укажите домен своего сайта.
3. Получите **клиентский ключ** `ysc1_…` и **серверный ключ** `ysc2_…`. **Для проверки токена IAM-токен не нужен**.
4. Перейдите в **Настройки → Yandex AntiSpam** и сохраните оба ключа.
5. Проверьте гостевой комментарий и отдельно вход/регистрацию в режиме инкогнито. Пройдите обычную и повторную отправку.

Официальная документация Яндекса:
- https://yandex.cloud/ru/docs/smartcaptcha/operations/create-captcha
- https://yandex.cloud/ru/docs/smartcaptcha/concepts/keys
- https://yandex.cloud/ru/docs/smartcaptcha/concepts/invisible-captcha
- https://yandex.cloud/ru/docs/smartcaptcha/operations/validate-captcha

## Настройки и события

- Перед созданием виджета браузер запрашивает актуальный режим по `admin-ajax.php` (без кеширования), поэтому включение видимой капчи работает и при включённом HTML-кеше страниц. При недоступности endpoint используется значение режима из HTML.
- Виджет по умолчанию невидимый. **Порог:** 3 отправки; **окно:** 10 минут (редактируются).
- Ошибки проверки или подозрительное содержимое комментария вызывают переход к видимому виджету на следующей загрузке формы.
- Honeypot-поле отсекает примитивных ботов.
- При временной сетевой недоступности сервиса API по умолчанию работает **fail-open** — доступность формы важнее. Это можно отключить. Отсутствие токена, неверный результат и неправильный host **всегда блокируются**.
- Админка содержит приблизительные агрегаты за 7 дней (успешные проверки, блокировки, недоступность, повышение риска) и последние 30 событий **без сохранения сырых IP, email, имён и текста сообщений**.
- Серверный ключ шифруется через AES-256-GCM ключом на базе WordPress salts, не выводится в HTML. Изменение WordPress salts делает сохранённый ключ нечитаемым: после смены необходимо ввести его заново.
- Для подсчёта повторов используется `REMOTE_ADDR` — настройте восстановление реального адреса на доверенном reverse proxy, иначе несколько людей за прокси могут получить видимый режим одновременно.
- Уведомление Yandex SmartCaptcha о обработке данных включено (щит **не** скрывается). Учтите требования политики конфиденциальности сайта.

## API для собственных форм

Тема или плагин может добавить виджет внутрь **своей** HTML-формы:

```php
<?php do_action('ysca_render', 'contact'); ?>
```

**Обязательно** вызовите серверную проверку **до** записи данных / отправки письма:

```php
$result = function_exists('ysca_verify_custom')
    ? ysca_verify_custom('contact')
    : true;
if (is_wp_error($result)) {
    // Не отправляйте письмо / не записывайте заявку.
    wp_die(esc_html($result->get_error_message()), 'Проверка', array('response' => 403));
}
```

Обе операции должны использовать одинаковый контекст (например `contact`). Контекст нужен для расчёта частоты. При интеграции с нестандартной авторизацией важно обеспечить прохождение **того же** серверного контроллера, которым сохраняется результат.

## Безопасность, совместимость и тестирование

- Административная форма: `manage_options` и `check_admin_referer`.
- Серверная проверка: только фиксированный HTTPS-endpoint Яндекса, `wp_remote_post` с таймаутом 7 с, без перенаправлений.
- Хост из ответа `status: ok` сравнивается с `home_url()` / `site_url()`.
- Отсутствие JavaScript приводит к отклонению защищённой отправки, а не к бесконтрольному пропуску.
- На отключенных и неподдерживаемых формах плагин не перехватывает запросы.
- Скрипт для комментариев подключается только там, где комментарии открыты; скрипт для `wp-login.php` — на экранах авторизации.
- Локальные smoke-тесты имитируют ответы API; на реальном WordPress 6.x с реальными ключами требуется интеграционное тестирование.
