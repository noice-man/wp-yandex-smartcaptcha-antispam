# Настройка Yandex SmartCaptcha AntiSpam — подробная инструкция

Страница этой инструкции: **https://ворд-пресс.рф/solutions/yandex-smartcaptcha-wordpress-setup/**

## 1. Создайте SmartCaptcha в Yandex Cloud

1. Войдите в https://console.yandex.cloud/ и выберите каталог.
2. Откройте сервис **SmartCaptcha → Создать капчу**.
3. Введите имя и добавьте сайт в список разрешённых доменов (`example.ru` без `https://`). Для `www` и других поддоменов учитывайте правила сервиса.
4. Выберите подходящее задание и сложность. Настройка внешнего вида влияет на видимый виджет и всплывающие задания.
5. Создайте капчу и откройте информацию о ней.

Справка: https://yandex.cloud/ru/docs/smartcaptcha/operations/create-captcha

## 2. Получите ключи

В карточке SmartCaptcha скопируйте:

- **Ключ клиента** — начинается с `ysc1_`. Он публичный и отображается в исходном коде сайта.
- **Ключ сервера** — начинается с `ysc2_`. Секретный; не отправляйте его другим людям и не размещайте в браузере, CSS, JavaScript, репозитории или скриншотах.

Это ключи самой SmartCaptcha. Не путайте их с IAM-токеном Yandex Cloud или API-ключом Yandex AI Studio.

Справка: https://yandex.cloud/ru/docs/smartcaptcha/concepts/keys

## 3. Установите плагин

1. В WordPress откройте **Плагины → Добавить новый → Загрузить плагин**.
2. Выберите архив `yandex-smartcaptcha-antispam-v1.0.0.zip`.
3. Нажмите **Установить** и **Активировать**.
4. Перейдите в **Настройки → Yandex AntiSpam**.
5. Введите ключи клиента и сервера, сохраните.
6. Убедитесь, что показано «Защита активна».

Серверный ключ шифруется в базе WordPress; при смене salts нужно ввести его повторно.

## 4. Проверьте формы

- По умолчанию включена защита стандартных комментариев WordPress, регистрации и восстановления пароля.
- **Вход по умолчанию не защищён**, чтобы неверная конфигурация не заблокировала администратора. Включайте вход после успешного теста капчи.
- Откройте комментарии или регистрацию в приватном окне браузера и отправьте тестовую форму.
- При первом запросе проверка обычно невидимая. Если Яндекс посчитает запрос подозрительным, он самостоятельно покажет всплывающее задание.
- Повторите три отправки в течение 10 минут с одного IP. На новой попытке должен появиться видимый виджет «Я не робот». Это не обязательно означает, что Яндекс покажет головоломку.
- Посмотрите раздел статистики в настройках плагина.

## 5. Настройте порог

Значения по умолчанию: три отправки за десять минут. Плагин запоминает попытки отдельно для IP и вида формы с помощью временных записей (`transient`). Даже при HTML-кешировании страницы JS запрашивает режим через `admin-ajax.php` с `cache: no-store`.

Серверное отклонение токена или подозрительные ссылки в комментарии усиливают проверку раньше порога.

## 6. Обработка сбоев Яндекса

По умолчанию **fail-open** действует только для сетевых сбоев, тайм-аутов и HTTP-ответов API, отличных от 200. Если такого поведения не хотите, выключите настройку «Не блокировать отправку при сетевой ошибке». При включённой защите формы отсутствие токена, негативная проверка Яндекса и несовпадение домена всегда блокируют отправку.

Для диагностики проверьте, что сервер WordPress может отправлять HTTPS-запросы на `https://smartcaptcha.cloud.yandex.ru/validate`, а браузер пользователя загружает `https://smartcaptcha.cloud.yandex.ru/captcha.js`.

## 7. Кеширование, прокси, данные

- Для статистики используется только агрегированная информация, сырые IP не сохраняются в журнал.
- Для порога используется IP из `REMOTE_ADDR` (не из произвольных `X-Forwarded-For`, которые можно подделать). Если у вас Cloudflare/Nginx/reverse proxy, настройте доверенный сервер на передачу реального IP.
- Сервис Яндекса обрабатывает данные пользователя, поэтому ссылка с уведомлением SmartCaptcha остаётся видимой. Проверьте политику обработки персональных данных на сайте.
- Если сервер в WordPress использует URL с кириллическим доменом (IDN), поддержка `intl`/`idn_to_ascii` полезна для сверки домена из ответа сервиса.

## 8. Ваши темы, CPT и плагины авторизации

Плагин не может автоматически защитить формы нестандартного плагина без его server-side integration. Разработчику нужно добавить вызов `do_action('ysca_render', 'custom-login')` **внутри своей формы**, а перед фактической обработкой POST вызвать `ysca_verify_custom('custom-login')`. Оба вызова обязательны. Подробности — в `README.md` исходного пакета.
